# -*- coding: utf-8 -*-
"""注释规范：把「说明式」注释改成「契约式」注释。

适用于 vbhelper/ 下全部 Python 源码。目标是让外部读者在不知道项目历史的前提下，
仍能判断一个模块能做什么、边界在哪、哪些约束不能动。
"""

## 一、三类注释，三种写法

### 1. 模块 docstring

写职责、边界、关键约束。三到六行，不超过十行。

```python
"""目录树扫描：把磁盘目录转成 Treeview 节点，维护展开缓存。

只读文件系统，不写项目文件。扫描在 ScanPool 线程里跑，结果经队列回主线程；
单目录超过 FANOUT_LIMIT 时只取前 N 项，避免一次创建上万个节点。
"""
```

禁止：用法示例、`python xxx.py` 运行说明、历史沿革、"本模块用于..."这类空话。

### 2. 公共函数/类 docstring

写契约：输入约束、返回值语义、异常、副作用。一句话摘要，必要时补两行说明。
私有函数（`_name`）只在逻辑非显然时写一行。

```python
def resolve(name: str, *, timeout: float = 5.0) -> str | None:
    """查询包的最新版本号。

    网络失败、包不存在、响应无法解析时返回 None，不抛异常；
    调用方负责区分「查不到」和「没有更新」。
    """
```

禁止：逐参数复述签名（`:param name: 名字`）、"这个函数用来..."、"调用示例："。

### 3. 行内注释

只写代码本身看不出来的信息：

- 平台限制（`# UpdateLayeredWindow 要求窗口已映射`）
- 协议怪癖（`# 该接口把 0 当作成功`）
- 性能取舍（`# 一次读 1MB，避免逐行 syscall`）
- 绕过原因（`# ttk 在 clam 主题下会画白底，改用自绘`）
- 不变量（`# 此处必须已持有 _lock`）

禁止：复述下一行代码、口语（"别像卡住了"、"太抽象"、"裸奔"）、感叹号、
无主语的碎片（"先这样"、"回头再说"）。

## 二、术语与格式

| 项 | 规定 |
|---|---|
| 语言 | 简体中文；专有名词保留英文（Tk、DPI、FTS、JWT） |
| 句末 | 陈述句用句号；短语式注释不加标点 |
| 人称 | 不用"我们""你"；用"调用方""本模块" |
| 时态 | 描述当前行为，不写"将要做""暂时" |
| 数字 | 阈值、上限、超时写明单位和来源 |
| 引用 | 不写 `计划 01 §3.2`、`docs/plan/xxx`；需要背景时写清约束本身，或引用 ADR 编号 |

## 三、必须清理的四类内容

1. **教程式**：`用法示例`、`用法:`、`示例:`、`python xxx.py`、`调用方式`。
2. **内部指代**：`计划 0x §`、`子代理 A/B/C`、`另一 agent`、`本次任务`、`TODO 待补`。
3. **法律自证**：`照抄 xxx 第 N 行`、`从 xxx 源码抽取`。改为在 NOTICE 统一声明来源。
4. **口语与情绪**：`搞`、`弄`、`别`、`吧`、`啊`、`嘛`、`凑合`、`裸奔`、`白嫖`、`秒开`、`卡住`。

## 四、保留什么

- 已有的平台坑、协议约束、性能说明——这些是注释里最有价值的部分，只改措辞，不删信息。
- 复杂算法的步骤编号。
- 公开 API 的行为承诺（幂等、线程安全、可取消）。
